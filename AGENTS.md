# SkillGap

Бот в MAX для девятиклассников, которые смотрят программы СПО. Показывает возможные стартовые должности, а дальше — требования рынка, Skill Gap и зарплаты. Профессию за пользователя не выбирает и профориентацией не является.

Источник продукта: `Техническое задание SkillGap 2.0.md`. Архитектура: `docs/architecture.md`.

## Продукт

- Связка справочника: код программы → квалификации → возможные должности → запросы вакансий.
- `work_roles` и `vacancy_queries` в `spo_program_vacancy_map.json` — поисковая модель SkillGap. Пользователю их не показывать как официальный список профессий. Официальный факт — код, название, квалификации, реквизиты ФГОС и ссылки на ФГОС/ПОП. Ограничения лежат в `_documentation` того же JSON.
- Рядом со списком должностей всегда оставлять пояснение: это возможные направления, не гарантия трудоустройства.
- Skill Gap считается по федеральной примерной программе, а если её нет — по ФГОС. Нельзя писать, что конкретный колледж «не учит» навыку.
- Статусы навыка: «Найдено», «Частично найдено», «Не найдено в анализируемом документе/программе». При совпадении показывать дисциплину, модуль или фрагмент.
- Зарплаты без цифр в вакансиях — текст «Нет данных». Тестовые данные помечать явно. Рядом с результатом хранить источник, дату и режим live/cache/test.
- Без явной просьбы не делать: «Следить за рынком», учебные планы колледжей, сравнение нескольких программ.

## Карта кода

| Путь | Зачем |
|---|---|
| `cmd/bot` | Процесс: БД, каталог, клиент MAX, воркеры, HTTP |
| `internal/maxapi` | HTTP-клиент `platform-api2.max.ru` и модели Update |
| `internal/handler` | `POST /webhook`, проверка секрета |
| `internal/worker` | Очередь и идемпотентность webhook |
| `internal/bot` | Сценарий диалога и сессия по `chat_id` |
| `internal/catalog` | Справочник СПО и регионы |
| `cmd/migrator` | Goose-миграции Postgres |
| `cmd/emulator` | Нагрузка и повтор webhook, не пользовательский сценарий |

Живые HTTP-маршруты: `POST /webhook`, `GET /metrics`. `shared/api/openapi.yaml` описывает несуществующий клиентский API и контуром SkillGap не является.

Сейчас реализован выбор направления: регион, программа, квалификация, должности, ссылка на источник. Кнопка «Запустить анализ» вызывает `analyzeStub` в `internal/bot/handler.go`. Вакансий, навыков, разбора программы, Skill Gap и зарплат в коде нет.

## MAX

Правило API: `.cursor/rules/max-api.mdc`. Локальная копия — `дока макса/`. При расхождении приоритет у https://dev.max.ru/docs-api.

Не ломать то, что уже зашито в клиент:

- Базовый URL `https://platform-api2.max.ru`. Токен только в заголовке `Authorization`, не в query.
- Production — webhook, не long polling. `MAX_WEBHOOK_URL` только `https://`.
- Секрет webhook — заголовок `X-Max-Bot-Api-Secret` (`internal/handler/middleware.go`).
- Сессия ключуется по `chat_id`. В `message_created` `user_id` часто пустой; `chat_id` брать через `Update.ResolvedChatID` (`message.recipient.chat_id`).
- Лимиты клиента: 25 rps глобально, 2 сообщения в секунду на чат. Дока платформы — не больше 30 rps.
- `GET /chats` не использовать.
- Ответ на inline-кнопку — `POST /answers` с `callback_id`, не второй `POST /messages`.

Callback-префиксы: `sg:begin`, `sg:help`, `sg:restart`, `sg:reg:`, `sg:p:`, `sg:q:`, `sg:analyze`. Подпись кнопки обрезать до 58 символов. В одном ряду callback-кнопок не больше 7 (у `link` — не больше 3). Клавиатура — до 30 рядов и 210 кнопок.

Подписка при старте, если задан `MAX_WEBHOOK_URL`: `bot_started`, `bot_added`, `bot_removed`, `bot_stopped`, `message_created`, `message_callback`.

## Каталог и окружение

- Путь справочника: `SKILLGAP_CATALOG_PATH`, иначе `spo_program_vacancy_map.json`.
- Регионы — коды «Работа России» в `internal/catalog/regions.go`. Быстрые кнопки — `PopularRegions`.
- Обязательные переменные процесса: `DATABASE_URL`, `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET`. Шаблон — `core.env.template`. Секреты не коммитить.
- Образ ставит корневые сертификаты Минцифры: без них `GET /me` к платформе не проходит.

## Как менять диалог

Новый шаг сценария добавлять в `internal/bot`: состояние в `session.go`, переход в `handler.go`, payload с префиксом `sg:`. Текст пользователю — на русском, коротко, с явным шагом. Поиск программ: точный код важнее подстроки названия, актуальные (`is_current`) выше исторических.

Анализ рынка не встраивать в handler напрямую. Следующий слой — пакеты из `docs/architecture.md` (`internal/vacancies` и разбор программы), handler только показывает результат.
